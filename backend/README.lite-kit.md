# AliceBridge backend (lite-kit)

Серверная часть для Android-приложения AliceBridge. Веб-интерфейса нет. Пользователь работает в Android-приложении; сервер на одном IP принимает DNS, HTTP и HTTPS и отдаёт обратную связь приложению через DNS TXT.

## Порядок подключения

1. Открыть AliceBridge. Если готовая колонка найдена по ADB, выбрать её и открыть панель управления.
2. Для новой колонки нажать «Начать настройку», дождаться root, выдать права в KernelSU и поднять хотспот.
3. Добавить колонку в «Доме с Алисой», выбрав сеть и пароль из AliceBridge.
4. Вернуться в AliceBridge и следить за прошивкой, перезагрузкой и ADB.
5. Пройти настройки OTA, аналитики, постоянного ADB, YAM и домашнего Wi-Fi.

## Правило прошивки

Фиксированная граница — **21 октября 2026 включительно**.

- Если дата установленной прошивки **позже** границы, ищется прошивка **этой же платформы** с максимальной датой **не позже 21.10.2026**.
- Если доступна сборка от 21 октября — берётся она. Иначе берётся самая свежая из более ранних; при нескольких сборках одной даты сравнивается числовая версия.
- Для обычной retail-сборки от 21 октября или раньше сервер отвечает `hasUpdate:false`. Исключение — заводская сборка с суффиксом `.factory`: ей предлагается выбранная проверенная retail-прошивка для той же платформы. Это необходимо после factory reset, когда колонка стартует на заводском образе 2021 года.
- Если платформа или дата не определены либо подходящего образа нет, сервер не выдаёт произвольную прошивку.
- Первая проверка может запустить подготовку образа. Пока загрузка не завершена и не проверена, манифест не выдаётся. Подготовка видна в статусе через DNS.

Платформы и версии читаются из каталога `http://144.76.194.29:62891/`. Загрузка — исключительно `<platform>/<version>/update.zip` с этого зеркала, метаданные — соседний `metadata.json`. Образы разных платформ лежат отдельно: `firmware/<platform>/<version>/`. Проверяются версия метаданных, длина HTTP, CRC32, SHA256 при наличии в метаданных и целостность ZIP либо SWUpdate CPIO. Вычисленный SHA256 сохраняется. Эти проверки подтверждают целостность передачи, а не подлинность подписи производителя; подпись OTA проверяет сама колонка.

В `config/reference-manifests.json` сохранена справочная таблица из [quasar-unlock](https://github.com/otomir23/quasar-unlock), commit — в `config/reference-source.json`, лицензия рядом. Справочные версии не подменяют правило даты. В quasar-unlock обновление предлагается лишь когда справочная числовая версия **новее** текущей; в исходном lite-kit откат выдавался при несовпадении с единственной выбранной версией. Здесь используется явное правило даты и отдельный образ каждой платформы.

Наличие платформы/ZIP в зеркале не гарантирует принятие отката или включение ADB на каждой модели. Возможны ограничения подписи, anti-rollback и доверия TLS. Сервер записывает фактические ответы и ошибки.

## Запуск

Нужны Python 3 с OpenSSL, ADB в PATH; дополнительных Python-пакетов нет. На Mac серверный адрес определяется по en0. Для другого адреса/хоста можно задать `LOCAL_IP`.

```sh
./start.sh       # macOS/Linux: для портов 53/80/443 нужны права администратора
./stop.sh
```

После успешного запуска `start.sh` показывает последние 30 строк `log/server.log` и новые строки в реальном времени. `Ctrl+C` закрывает только просмотр: сервер работает отдельным процессом. Для остановки используйте `sudo /bin/bash ./stop.sh`. `local-start.sh` сохраняет режим запуска без просмотра логов.

Без административных прав доступен локальный тест:

```sh
./local-start.sh --preview  # DNS 5354, HTTP 8080, HTTPS 8443; не подходит для обычного подключения колонки
```

Проверка/предварительное скачивание образа без подключения колонки:

```sh
python3 scripts/prepare_firmware.py yandexmini
```

Скрипт выбирает образ автоматически по тому же правилу даты. Никакой файл не отправляется колонке самим скриптом.

На сервере должны быть доступны TCP 53/80/443 и UDP 53. В приложении задаётся IP этого сервера. При переносе на общий IP нужно открыть эти порты на сервере/маршрутизаторе и указать новый адрес в Android-приложении. Никаких запросов активации к Яндексу сервер по умолчанию не делает (`ALLOW_YANDEX_UPSTREAM=0`). DNS для остальных имён рекурсивно пересылается публичным DNS.

## Обратная связь

Запрос приложения: TCP DNS TXT `status.<случайный-id-сессии>.alicebridge.invalid`. Ответ — JSON, разбитый на DNS TXT строки. Приложение объединяет строки и показывает платформу, текущую/целевую/подтверждённую версию, последний HTTP-код, ошибку TLS, подготовку образа, переданные байты OTA и ADB со стороны сервера. HTTPS-трафик колонки на телефоне не расшифровывается.

Сервер соотносит DNS и HTTP по исходному адресу. Несколько активных сессий за одним внешним IP отмечаются как неоднозначные: чужой статус не приписывается колонке. Разный выходной IP DNS и HTTPS (VPN/раздельные маршруты) также не позволяет надёжно связать их.

После перезагрузки и смены DHCP-адреса запросы с тем же `device_id` объединяются. Android-клиент дополнительно отслеживает IP колонки по MAC в таблице соседей хотспота. ADB повторяется; успех подтверждается ответом `shell id`, root — `uid=0`. Передача всех байтов OTA обозначает **только передачу**, установка подтверждается новой версией в запросе/ADB.

События сохраняются в `log/events.jsonl`: DNS-статусы, пары запрос/ответ, локальные JSON, ошибки, диапазоны OTA, ADB. Диапазоны объединяются без двойного подсчёта. Некорректные Range возвращают 416, возобновление — 206. Авторизация и секретные поля маскируются. ADB наблюдателя использует отдельный Unix socket и не останавливает общий ADB пользователя.

## Проверки

```sh
python3 -m unittest discover -s tests -v
```

Тесты проверяют границу даты, выбор ближайшей более ранней сборки, разделение платформ, запрет неправильного образа, Range/HEAD, неполную передачу, смену IP, DNS-статусы, изоляцию сессий и отсутствие обращений к Яндексу в локальном режиме.

## Временно выбранный локальный образ Lite 1

По запросу пользователя выбран `yandexmicro / 0.369.1.46.4778262442.20261013.297` от 13 октября, предоставленный локальным файлом. Размер 66 814 464 байта, CRC32 371630625, SHA256 `74d4e8fae375b2ad1757761e01caf6be0209d216328ce1a942dbef38c8f20d11`. Это SWUpdate CPIO с проверенными внутренними CRC. Выбор хранится в `run/selections.json` и перечитывается перед выдачей манифеста. Другим платформам этот образ не выдаётся.

В извлечённом наборе CA этого образа 141 сертификат, AAA Certificate Services присутствует; цепочка локального сервера проходит `openssl verify`. Это офлайн-проверка доверия, не подтверждение установки или ADB. Предыдущий локальный образ от 19 октября сохранён, но больше не выбран: в его наборе CA AAA отсутствует и проверка той же цепочки завершается ошибкой.

## Локальный образ Mini 1 от 13 октября

Для `yandexmini` выбран предоставленный пользователем `1.369.4.46.4778368993.20261013.zip`: 53 033 896 байт, CRC32 863624814, SHA256 `dab90d70a8e814539060100a25c44c48c2e45e36b032015bfa1188607d49d5d1`. Расширение `.zip` не отражает формат: это XZ → TAR → SWUpdate CPIO. Валидатор проверяет весь поток XZ, заголовки TAR и внутренний CPIO без исполнения или извлечения программ на диск. Повреждённый XZ footer и внутренние CRC отклоняются.

Из этого образа отдельно для диагностики извлечён `/system/vendor/quasar/certs/ca-certificates.crt`: 141 сертификат, AAA Certificate Services присутствует, цепочка локального сервера проходит `openssl verify`. Это офлайн-проверка набора CA, а не подтверждение ADB или успешной установки на колонке. Прошивка Mini 1 никогда не выдаётся Lite 1 (`yandexmicro`).
