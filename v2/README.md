# AliceBridge 1.0.0

Новый Android-клиент в отдельном Gradle-проекте. Сохраняет тёмный интерфейс и сиреневые акценты AliceBridge. Релиз объединяет сетевой сеанс, профильные действия и управление колонкой. Совместимость полного сценария проверяется отдельно для каждой модели.

## Реализовано

- Выбор модели и инструкция сброса до подготовки телефона; один смартфон с AliceBridge и «Домом с Алисой».
- Способ не выбран до действия пользователя; инструкция раскрывается после выбора. DFRoot встроен, запуск закрыт до установки/выбора KernelSU; выбор установленного KernelSU, проверка уже действующего root, напоминание о выдаче прав в KernelSU и перезагрузке телефона по окончании работы.
- Переход к подключению колонки закрыт до подтверждения точки, DNS UDP/TCP для трёх служебных доменов, отсутствия обходного AAAA-ответа, обычного DNS, HTTP 204 и версии формата обратной связи. Для DFRoot проверяется сам запущенный DNS-прокси; для Shizuku проверка повторяется после старта AP. Реальный путь колонки подтверждается только её последующим трафиком. При стартовой ошибке точка останавливается.
- Точка 2,4 ГГц, пересылка всех DNS UDP/TCP в выбранный сервер, опциональный WPA/WPA2 только в DFRoot и выключенный по умолчанию.
- Shizuku: разрешение API, UserService, тестовая сеть/TUN, SOCKS и предварительная проверка DNS UDP/TCP + HTTP. Предварительная проверка телефона **не является доказательством работы клиентского пути**. Сетевой режим пока Android 13+; DFRoot — Android 12L+.
- Инструкция HyperOS/Shevery и обычной Shizuku; подсказки о MediaTek UserService, thedjchi/Next и совместимости нового Shevery.
- Сохранение модели, способа, адреса сервера, SSID/пароля, выбранной колонки и версии. После перезапуска можно отдельно восстановить прежнюю точку.
- Встроенный ADB: проверка доступности независимо от повторного check_updates, чтение версии, UID, MAC/serial, ядра и свободного места; выбор при нескольких доступных устройствах.
- Состояние выводится по наблюдениям, а выполненные операции хранятся отдельно. Повторный запрос проверки обновления меняет визуальный этап и не запускает повторную запись boot.
- Копирование SSID/пароля значками справа. Каждое открытие «Дома с Алисой» сначала принудительно останавливает приложение через root/работающий Shizuku UserService.
- Отдельные страницы журнала и настроек; компактные карточки журнала сохраняют полный текст. ZIP диагностики сразу открывает «Поделиться»; пароль и токен сеанса исключаются.

## Профильные действия и управление

- Отдельный модуль `station` с состоянием выбранного подключения: старый глобальный `Session` не используется.
- Станция 1: проверка модели, независимая резервная копия boot на телефоне, проверка размера и SHA-256 загруженного root-образа, запись и полное чтение раздела для сверки, сохранение контрольной точки перед перезагрузкой, проверка новой загрузки/root и собственная блокировка OTA. Не требует совпадения исходного boot с единственным заводским хешем. Повторная запись boot при ожидании перезагрузки запрещена. Проверенный бэкап сохраняется на телефоне, временные образы с колонки удаляются после подтверждения защиты OTA.
- Linux Mini/Lite/Midi: основной и резервный способ OTA, постоянный ADB, аналитика. Результат каждого скрипта проверяется отдельно; обрыв транспорта приостанавливает последовательность.
- Макс: перенесён отдельный метод с проверкой точной модели/сборки/ядра. Непроверенные Linux-установщики на Android Макс блокируются явным сообщением.
- Fastfetch запускается автоматически после обязательной настройки; ошибка отображается отдельным шагом с возможностью пропустить.
- YAM, YSE/Entware, Dropbear, Zsh и initialfox apkg — только по кнопке с подтверждением. Зависимости Entware/Zsh и YAM передаются из APK. Настройка Zsh включает PATH, тему adam1, login-оболочку и переключение свободного терминала.
- YAM: отдельные вкладки пакетов и плагинов, поиск, фильтр установленных, установка/удаление/включение, запуск и журнал. Entware: отдельный каталог с установкой/удалением пакетов.
- Терминал использует настоящий PTY и локальный xterm.js, поддерживает интерактивные программы. Для Станции 1 используется её root-транспорт.
- Домашний Wi-Fi: отдельный экран, глазок пароля, подстановка текущей сети телефона через root. Для Станции 1 используется Android Wi-Fi helper, для Linux — активный supplicant/контроллер и запасные пути. Временная точка выключается только после проверки идентификатора колонки и нового SSID.
- При возобновлении сначала проверяется последний адрес ADB, до запуска DFRoot/точки/DNS. Для незавершённого перехода в домашнюю сеть выполняется поиск нового адреса.

## Лайт 2 и Мини 3: factory → retail CA

Модель выбирается один раз на старте. Для `lite2/plum` и `mini3/bergamot` приложение запрашивает у backend отдельный режим **без OTA и без отката**, проверяет его подтверждение до подключения колонки и сохраняет этот режим отдельным heartbeat во время длительных операций.

- Лайт 2: root ADB в factory, определение MTD с именем `system` и связанного UBI `rootfs`, резервная копия исходного CA, запись проверенного бандла из APK, переход в normal и проверка SHA-256 после новой загрузки.
- Мини 3: проверка старого factory-4/factory-6 и `rootfstype=ramfs`; исходный retail-бандл сохраняется побайтно и дополняется только корнем AAA. Перед перезагрузкой создаются маркеры ADB и сохраняется Wi-Fi с `update_config=0`.
- Номер MTD/UBI не зафиксирован. Не используются `dd`, стирание или форматирование разделов. При неверной разметке, отсутствующем CA, неожиданной ссылке, ошибке хеша или неизвестных переменных загрузки запись/перезагрузка останавливаются.
- Старый CA сохраняется в `.orig` на retail-разделе и в приватном каталоге приложения. Это резервная копия trust store, а не OTA-кэша: OTA-кэш по кнопке просто удаляется.
- Мини 3 использует отдельные статические ARMv7 Dropbear/Dropbearkey из вики: её ядро aarch64, а штатный userspace armhf. Выбор SSH делается по модели. При 32-битном ядре ARM64-установщики YAM/apkg закрыты; Fastfetch можно пропустить. YSE/Entware и Zsh имеют отдельные ARMv7/ARM64-комплекты.
- Для Мини 3 рекомендуется установить SSH до перехода на обычный DNS: сервер Яндекса может отключить ADB.

Backend обязан подтверждать `retail_ca_mode=plum/bergamot`; старый сервер блокирует начало такого сеанса. Новая версия backend подготовлена отдельно; активация публичной службы производится отдельным действием.

Источники: [Лайт 2](https://hackalice.me/start/retail-ca/), [Мини 3](https://hackalice.me/start/retail-ca-mini3/). CA-активы проверены по опубликованному SHA-256 бандла и DER-отпечатку AAA. На физических Лайт 2/Мини 3 этот перенос пока не проверялся.

## Ограничения проверки

APK собирается, модульные проверки и lint проходят; перенос не является подтверждением работы на всех моделях. Физический проход root/перезагрузки и установки компонентов нужно проверять на соответствующей колонке. Обновления APK проверяются при запуске и вручную в настройках; предложение обновиться занимает весь экран.

## Локальный сервер

По умолчанию DNS `78.24.223.83`; меняется в настройках клиента. Для собственного локального сервера укажите его доступный телефону IPv4. Мобильный интернет сам по себе не даёт маршрута к локальному IP Mac; при таком сервере нужен доступный локальный uplink, например совместимая работа Wi-Fi и AP на телефоне. Требуется доступ телефона до Mac, DNS TCP/UDP 53 и HTTP/HTTPS 80/443 на сервере. При восстановлении используется адрес сохранённого сеанса.

Для локального теста используется `/Users/nikitawtern/Desktop/lite-kit`. Локальная доработка `control.py` добавляет `feedback_schema=2`, `server_boot`, `check_event_id`, `check_event_time`, номер цикла передачи, отказ от неоднозначного/устаревшего статуса и сброс старого подтверждения версии. Публичный сервер должен поддерживать этот формат статуса; обновление backend публикуется вместе с релизом.

Запуск существующим скриптом:

```sh
sudo /bin/bash /Users/nikitawtern/Desktop/lite-kit/start.sh
```

Старый backend без полей номера цикла не позволяет достоверно отображать новые переходы этапов. Не заменять их догадкой по старой строке статуса.

## Сборка и проверки

```sh
JAVA_HOME=/Library/Java/JavaVirtualMachines/jdk-17.jdk/Contents/Home \
ANDROID_HOME=/Users/nikitawtern/Library/Android/sdk \
./gradlew :app:assembleRelease :app:testReleaseUnitTest :app:lintRelease :bridge:lintRelease :station:lintRelease :station:testReleaseUnitTest :domain:test
```

APK: `app/build/outputs/apk/release/app-release.apk`, ARM64, Android 12L+. `applicationId=ab.root` сохранён из-за путей проверенного нативного bootstrap и прав KernelSU. Установка заменяет прежнюю AliceBridge; это не параллельное приложение. Данные v2 пишутся в отдельные файлы; старые исходники не переписаны.

## Происхождение адаптеров

Сетевые адаптеры, DNS wire parser, hostapd helper, DFRoot runner и нативные файлы перенесены из текущей рабочей AliceBridge. Состояние и lifecycle старой `Session`/`BridgeService` не используются. Контроллер сеанса, хранилище, доменная модель и Compose-интерфейс новые. HEV AAR сохраняет свой Java/JNI namespace. Лицензии и происхождение двоичных компонентов должны сопровождать будущую публикацию исходников/релиза.

Исследования находятся в `../docs/research/`, основное ТЗ — `../docs/AliceBridge-2.0-ТЗ.md`.
