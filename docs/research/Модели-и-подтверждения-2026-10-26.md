# Подтверждения по моделям на 26.10.2026

Проверены два журнала публичного сервера: текущий `events.jsonl` и архив `events.jsonl.1.gz`. Сохранённый обезличенный агрегат — `server-root-evidence-2026-10-26.json`. Это срез, а не гарантия полноты всей истории сервера.

В них нет событий `adb` с выводом `uid=0`. Поэтому **серверные логи не позволяют подтвердить root ни для одной модели**. Это не означает, что root не получен: приложение пока не отправляет серверу такой проверенный результат, а сервер за NAT не может проверять ADB колонки напрямую.

Число событий не равно числу колонок: повторные передачи и тестовые запросы входят в журналы. Передача ZIP, новый запрос HTTP, повторное появление устройства и подтверждение текущей версии — отдельные факты, не доказательство UID=0 и не доказательство постоянства root.

## Дополнительная диагностика приложения

- **Мини 1:** в диагностическом снимке есть `UID=0`, версия `1.305.4.16.3237824040.20250721`; есть также ADB-события `shell id → uid=0`, относящиеся к тому же выбранному адресу. Это подтверждение конкретного устройства/сеанса.
- **Миди:** есть снимок `UID=0` у `Yandex Cucumber DVT2`, `factory-10`. Инженерную заводскую сборку нельзя выдавать за подтверждение метода на розничной Миди.
- **Лайт 1 и Мини 2:** найдены события ADB с `uid=0`, однако конечный снимок уже не содержит того же выбранного адреса. До восстановления привязки события к устройству это не независимое подтверждение точной модели/прошивки. Версия последнего backend status не обязательно совпадает с версией в момент ADB-события.
- **Станция 1, Лайт 2 и другие:** сообщения пользователей об успешном проходе сохраняются как отдельный вид доказательств. Они не превращаются в серверное подтверждение root.

Обезличенные указатели на исходные архивы: `app-root-evidence-2026-10-26.json` и `app-adb-root-events-2026-10-26.json`. В публичную документацию не переносить адреса, токены и полные пользовательские архивы.

## Что записывать в 2.0

Отдельно хранить события: версия прочитана из запроса; файл передан; версия прочитана по ADB; root подтверждён командой `id`; профильная настройка проверена; ADB/root сохранились после перезапуска. У каждого — время, модель/ревизия, версия, boot ID и локальный идентификатор устройства. Отправка обезличенного результата на сервер должна быть отдельным контрактом, а не попыткой вывести root из HTTP-статуса. В этой dev-сборке передача такой телеметрии не реализована.
