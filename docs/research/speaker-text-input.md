# Произвольный текст через штатную Алису

Проверено 25 октября 2026 на подключённой Станции Лайт 1 через root ADB.

В `/system/vendor/quasar/maind --cli` есть команда `q` — Text Input Query.
Она передаёт текст основному процессу Алисы с уже действующей авторизацией самой колонки. Получать OAuth/Glagol токен в AliceBridge для этого пути не требуется. Колонке нужен доступ к облаку Яндекса.

Тестовый ввод в stdin консоли:

```text
q
Повтори за мной: Проверка связи из AliceBridge.
```

Подтверждение в `/data/quasar/daemons_logs/maind.log` для тестового запроса:

```text
onAliceStateChanged: SPEAKING, outputSpeech='Окей, повторяю: «проверка связи из alicebridge».'
onHandleDirectiveCompleted completed=SUCCESS ... tts_play_placeholder
```

Первая проверка уже была успешной; первоначальный вывод CLI сам по себе не содержал подтверждения, результат найден в журнале основного процесса. Во время теста соединение с телефоном пропало, журнал дочитан прямым ADB к колонке. Звуковое подтверждение от пользователя пока не получено.

## Ограничения и реализация в приложении

- Это текстовый запрос ассистенту, а не прямой вызов TTS: может добавляться «Окей, повторяю», нормализоваться регистр/произношение. Нельзя обещать побуквальное воспроизведение.
- После ответа запускается слушание; в реализации нужно завершать тестовый диалог командой `c` после завершения TTS, затем закрывать клиент через `x`.
- Отправлять текст после подключения CLI к возможностям основного процесса; одного запуска процесса недостаточно для подтверждения готовности.
- Успех подтверждать событием TTS именно тестового запроса, а не кодом выхода CLI.
- Текст в stdin следует передавать как данные, без интерполяции в shell; запретить/нормализовать перевод строки, чтобы строка не стала командой консоли.
- Нужен общий лимит времени, очистка только собственного процесса, защита от параллельных голосовых заданий.
- Нельзя выдавать полный журнал диалогов/секреты колонки в журнал AliceBridge.
- Проверена Лайт 1. Остальные модели, особенно Android Станция 1, требуют отдельной проверки наличия этого CLI.

Для произнесения текста через специальный сценарий без пользовательского запроса используется Glagol `serverAction` / `personal_assistant.scenarios.quasar.iot.repeat_phrase` со строковым слотом `phrase_to_repeat`. Это видно в исходниках AlexxIT/YandexStation и ma-provider-yandex-station. Штатный Glagol-клиент требует conversationToken. Этот путь на устройстве в рамках проверки не тестировался.
