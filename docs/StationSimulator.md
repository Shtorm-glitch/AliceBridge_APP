# Симулятор запросов станции

Подключите Mac к точке AliceBridge, запущенной приложением в режиме Shizuku.
Запустите из Terminal:

```sh
/Users/nikitawtern/Desktop/AliceApp2/tools/station-simulator.command
```

Шлюз и DNS определяются по маршруту Mac. Если активен VPN или другой интерфейс,
отключите его на время теста либо явно передайте `--dns IP_ШЛЮЗА_ТЕЛЕФОНА`.

Проверки выполняются в следующем порядке:

1. UDP/TCP DNS трёх служебных доменов через DNS хотспота.
2. AAAA: при IPv4-сервере не должен выдаваться обходной IPv6-адрес.
3. Прямой DNS к серверу и 1.1.1.1: проверка принудительной пересылки DNS.
4. Обычный DNS example.com, HTTP/HTTPS `generate_204`.
5. HTTPS `check_updates`: HTTP-статус и полный JSON с версией прошивки.
6. При предложенной прошивке — только Range 0–4095, проверка HTTP 206.
7. `get_sync_info`: ответ записывается, содержимое не выполняется.
8. Обычный HTTPS example.com для проверки маршрута остального трафика.

К служебным HTTP/HTTPS-доменам запрос идёт лишь когда DNS вернул настроенный
backend (по умолчанию 78.24.223.83). При другом ответе запрос пропускается и
отмечается ошибка DNS; запрос на настоящий сервис Яндекса не отправляется.
Все HTTP-соединения создаются непосредственно к IP из проверки, с правильными
Host/SNI, без системного HTTP-прокси и DNS-кэша браузера.

В комплекте публичный корень AAA Certificate Services. Сначала проверяется TLS
с ним; при неудаче отдельно проверяется доставка HTTPS без проверки цепочки.
Успех второй проверки не подтверждает доверие сертификату на реальной колонке.

Другие модели/версии и наблюдение:

```sh
python3 tools/station_simulator.py --model yandexstation_2 --version 5000000921 --include-sync
python3 tools/station_simulator.py --watch --interval 15
```

Статусы печатаются сразу. Каждый проход сохраняет отдельный JSON в
`diagnostics/station-simulator/`. ADB и саму прошивку симулятор не исполняет;
попытки приложения подключиться к Mac по ADB будут без ответа.
