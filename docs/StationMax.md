# Макс YNDX-0008 без Zigbee — экспериментальная поддержка

Целевая прошивка: **5000000921**, внутренний build ID
`PPR1.180610.011.5000000921`, Android 9, aarch64, ядро 4.9.113.
Образ от 16 октября 2026 проверен по структуре ZIP, CRC32 и SHA-256.
IoSDK этой прошивки доверяет сертификату текущего сервера AliceBridge.

До ADB используется существующий DNS/OTA-сценарий приложения.
При уже работающем ADB выберите колонку и нажмите «Получить root Макс».
Авторизацию ADB на новом устройстве может потребоваться выполнить отдельно.

После подключения приложение:

1. Проверяет модель, build ID, Android, архитектуру и ядро.
2. Передаёт проверенные `root-bridge` и `permissive` из предоставленного набора.
3. Запускает один `esc-bridge` и ждёт подтверждения worker READY.
4. Применяет cache guard и проверяет владельцев/права `/cache/recovery` и `/cache`.
5. Выполняет `esc-permissive check`, затем включает Permissive и сверяет readback.
6. Проверяет UID 0, capabilities и init-SID root worker.

Boot, vbmeta, recovery и системные разделы этим root-сценарием не прошиваются.
Это процессный root в текущей сессии; обычный adbd остаётся shell UID 2000.
После перезагрузки runtime root и Permissive нужно получить заново.
В панели можно включить «Восстанавливать root и установленный YAM после
перезагрузки». Выбор сохраняется для MAC конкретной колонки после первого
успешного root. При активной сессии AliceBridge приложение снова проверит
сборку и получит root после возвращения ADB. Установка YAM остаётся ручной.
Установленный YAM запускается через root worker с `nohup`, перенаправлением
stdin/stdout/stderr и проверкой API через ADB-forward на localhost:8099.
Поддерживается как каталог приложения `/data/quazar/yam/bin/yamd`, так и
`/data/yam/yamd` из инструкции OpenWrt. Пакеты и Lua-плагины доступны в YAM.
На Макс не используется Buildroot `start-stop-daemon` и не изменяется rc.local.
Это не автономный постоянный root: без телефона или доступного ADB восстановление
не выполняется. Интернет и DNS домашней сети сами по себе ADB не гарантируют.
Закрытие сессии AliceBridge также закрывает соединение с root worker.
После ошибки второй экземпляр exploit на той же загрузке автоматически не запускается.
Ограничение сохраняется на телефоне и привязано к boot ID, а не к IP.

Инструкция `yandex_station_max_autoroot_guide.md` описывает YNDX-00053 и
`5000000914` с другими kernel offsets. Этот выпуск не заявляет поддержку
этой сборки: необходим соответствующий проверенный бинарник. Для неё нельзя
использовать наш `permissive` от 0921. Настройки OpenWrt автоматически не
разворачиваются. В исходной инструкции постоянный `/tmp/autoroot.lock` на
роутере противоречит повторному запуску после reboot только колонки: нужен
контроль boot ID колонки и проверка результатов, а не длины raw ADB-ответа.

Cache guard — дополнительная защита, **полное отключение OTA не подтверждено**.
SSH, интерактивный root PTY и смена домашней Wi-Fi сети Макс в этом выпуске
не заявлены: Android отличается от Buildroot. Их кнопки для Макс скрыты.
APKG и fastfetch используют отдельный root worker; также требуют проверки на устройстве.

Реального Макс у разработчика приложения нет. Проверены образ, совместимость
сертификатов, ограничения модели/сборки, протокол bridge и сборка APK.
Реальное получение root и повторный проход после reboot должны подтвердить тестировщики.
При ошибке отправьте ZIP из «Журнал → Поделиться диагностикой».
