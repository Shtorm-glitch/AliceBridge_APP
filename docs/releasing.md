# Публикация обновлений AliceBridge

Для каждого релиза увеличить `versionCode` и `versionName` в `app/build.gradle`, собрать и проверить APK с прежним ключом подписи.

На сервере `78.24.223.83` в `/var/www/alicebridge-downloads/` публикуются:

- `AliceBridge-<versionName>.apk` — версия из APK должна совпадать с именем;
- `AliceBridge-update.json` — `versionCode`, `versionName`, `url`, `sha256`, `size`, `changes` (массив строк).

Текущий образец манифеста: `releases/AliceBridge-update.json`. Сначала загрузить и проверить APK, затем атомарно заменить манифест. Для нового имени APK добавить точный location в `/etc/nginx/conf.d/alicebridge-downloads.conf`; JSON отдавать с `application/json` и `Cache-Control: no-cache`.

Поддерживать три ссылки:

- `/AliceBridge-<versionName>.apk` — каноническая ссылка для встроенного обновления;
- `/AliceBridge.apk` — актуальная сборка;
- `/AliceBridge-0.4.16.apk` — прежняя распространённая ссылка, тоже должна отдавать актуальный APK. Внутри не менять номер новой версии на 0.4.16.

Встроенная проверка выполняется при каждом открытии главного экрана. Пропуск не сохраняется. Загрузчик сверяет размер, SHA-256, имя пакета, новую версию и подпись с установленным приложением. Установка подтверждается стандартным установщиком Android; при первом обновлении Android может попросить разрешить установку из AliceBridge.

Тестовая сборка 0.4.21/code 33 использовалась только как локальный подписанный образец для проверки загрузчика. Она не публиковалась как релиз и не устанавливалась на телефон.
